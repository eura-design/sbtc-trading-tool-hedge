=====================================================
 우리 시스템 — 상황별 확인표            2026-08-23
=====================================================
 이 문서는 "우리 화면에서만 매매할 때" 기준이다.
 바이낸스 앱·웹으로 주문하면 규칙이 달라진다 -> 맨 아래 [밖에서 주문했을 때]

[외울 건 두 줄]
  1. 청산은 우리 화면에서 한다
  2. 추가진입(물타기) 주문을 걸어뒀으면 컴퓨터를 켜둔다
  나머지는 시스템이 알아서 한다.

[표시 읽는 법]
  ✔ 켜도 꺼도 됨   ⚠ 조건부   ✖ 안 됨

-----------------------------------------------------
 A. 들어가기
-----------------------------------------------------
 1) 시장가 진입 (플랜 박스 -> 시장가)
    즉시 체결되고 익절·손절이 0.3초 안에 자동으로 걸린다.
    ✔ 체결 뒤엔 꺼도 된다 — 익절·손절이 거래소에 있다
    ⚠ "SL 등록 실패" 경고가 뜨면 절대 끄지 말 것 (무방비 상태다)
    ⚠ 슬리피지 0.3% 넘으면 경고가 뜬다. 익절·손절 가격을 눈으로 확인할 것

 2) 지정가 진입 (플랜 박스 -> 지정가)
    진입·손절·익절 **세 개가 한꺼번에** 거래소에 올라간다.
    ✔ 걸어두고 꺼도 된다 (2026-08-23 실거래로 확인 완료)
    ⚠ 익절은 자주 거절된다 — 익절가가 "이미 지나온 자리"면 거래소가 막는다.
      그때는 손절만 걸린다. 돈을 잃을 위험은 없고, 켜두면 체결 시 다시 걸어준다
    ⚠ 체결 전까지 화면엔 익절·손절이 안 보인다 (플랜 박스가 같은 값을 이미 보여주므로)
    ⚠ 주문 직후 문구를 볼 것
        "지정가 주문 + TP/SL 등록 완료"  -> 꺼도 됨
        "익절 사전 등록 실패"            -> 꺼도 됨 (손절은 걸렸다)
        "⚠ 손절 사전 등록 실패"          -> 끄지 말 것

 3) 롱과 숏을 동시에 들기
    ✔ 된다. 완전히 별개로 관리된다 (헷지모드)
    ⚠ 레버리지만은 롱·숏이 같은 값을 쓴다 — 거래소가 코인 단위로만 받는다
    ⚠ 같은 방향에 포지션이 있으면 그쪽 플랜 박스는 그릴 수 없다 (청산 후 가능)

-----------------------------------------------------
 B. 익절·손절 손보기
-----------------------------------------------------
 4) 차트에서 선을 끌어 옮긴다
    ✔ 된다. 옮긴 자리로 다시 걸린다
    ⚠ 옮기는 사이 0.1초쯤 손절이 없는 순간이 있다 (취소 -> 재등록 순서라 어쩔 수 없다)

 5) 없던 익절·손절을 새로 건다 (+TP / +SL 버튼)
    ✔ 된다. 버튼을 **끌어야** 등록된다 (클릭만으론 아무 일도 없음 — 오클릭 방지)
    ⚠ 가격이 말이 안 되면 거래소가 거절하고 빨간 배너가 뜬다

 6) 익절·손절을 지운다 (× 버튼)
    ✔ 된다. 한 번에 지워진다
    ⚠ 손절을 지우면 그 포지션은 무방비다 -> 1분 안에 빨간 경보가 뜬다. 정상 동작이다

 7) 미체결 주문의 가격을 바꾼다 (박스 가로선 드래그)
    ✔ 된다. 미리 걸어둔 익절·손절도 같이 다시 걸린다
    ⚠ 주문번호가 바뀐다 (취소 후 재등록이므로)

 8) 미체결 주문을 취소한다
    ✔ 된다. 딸려 있던 익절·손절도 같이 내려간다

-----------------------------------------------------
 C. 물타기 · 나눠 익절
-----------------------------------------------------
 9) 추가 진입 (물타기)
    ✔ 된다. 시장가·지정가 둘 다
    ✔ 손절은 자동으로 늘어난 포지션 전부를 덮는다 (따로 손볼 것 없음)
    ⚠ **지정가 추가진입을 걸어뒀으면 컴퓨터를 켜둘 것** — 이 문서에서 가장 중요하다.
      이유는 아래 15)

10) 분할 익절 (여러 가격에 나눠서)
    ✔ 된다. 최소 0.001 단위
    ⚠ 슬라이더는 "남은 것의 몇 %"다 (포지션 전체가 아니다)
    ⚠ 다 채우지 않아도 된다. 남는 물량은 "잔여"로 표시될 뿐 문제가 아니다

11) 단일 익절 + 분할 익절 같이 걸기
    ✔ 된다. 서로 취소하지 않는다 (2026-08-23 실거래로 확인)
    예) 82,000에 40% 익절 + 나머지는 85,000에 전부  -> 가능
    ⚠ 어느 쪽이 먼저 터지든 합계는 포지션을 넘지 않는다

12) 일부만 청산
    ✔ 된다. 분할 익절이 남은 비율에 맞춰 자동으로 다시 걸린다
    ⚠ 포지션 크기를 못 읽으면 분할 익절을 건드리지 않고 청산만 한다 + 경고가 뜬다.
      그때는 분할 TP 카드에서 수량을 직접 확인할 것

13) 전량 청산
    ✔ 된다. 그 방향의 익절·손절·분할익절·추가진입을 **전부 같이** 치운다
    ⚠ 반대쪽 포지션은 건드리지 않는다

-----------------------------------------------------
 D. 저절로 일어나는 일
-----------------------------------------------------
14) 손절이나 익절이 저절로 터졌다
    ✔ 분할 익절은 거래소가 알아서 지운다
    ✔ 남은 추가진입 주문은 우리 시스템이 3초 안에 치운다 (2026-08-23 추가)
    ⚠ 단, 컴퓨터가 켜져 있어야 한다

15) 컴퓨터를 꺼둔 사이에 포지션이 종료됐다  ★ 유일하게 남은 위험
    ✖ 추가진입 주문이 안 치워진다. 치울 사람이 없다
    -> 나중에 그 가격에 닿으면 **손절 없는 새 포지션이 혼자 열린다**
    -> 다시 켜면 1분 안에 치우지만, 그전에 체결되면 늦다
    대책: 자기 전에 추가진입 주문을 취소하거나, 컴퓨터를 켜둔다

16) 하루 손실이 한도(총자본 4%)에 닿았다
    ✖ 새 주문이 막힌다. 정상 동작이다
    ⚠ 이미 체결된 포지션은 그대로 굴러간다. 청산은 계속 된다
    ⚠ 세계표준시 0시(한국 오전 9시)에 초기화된다

17) 백엔드가 멈추거나 죽었다
    ✔ 잔고 옆 점이 10초 안에 빨갛게 변하고 "server.js 실행 확인" 문구가 뜬다
    ✔ 멈춘 사이에 누른 주문은 나가지 않는다. 깨어날 때 자동으로 취소된다
    -> 점이 빨간색이면 주문하지 말고 창을 다 닫은 뒤 start.bat 다시 실행

-----------------------------------------------------
 E. 아예 안 되는 것
-----------------------------------------------------
 · 트레일링 스톱 — 우리 시스템에 개념이 없다. 거래소에 있어도 화면에 안 뜬다
 · BTC 외 코인 — 포지션도 주문도 아무것도 안 보인다
 · 같은 방향에 진입 대기 주문이 2개 이상 — 하나만 보인다

-----------------------------------------------------
 F. 밖에서(바이낸스 앱·웹) 주문했을 때
-----------------------------------------------------
 보인다   : 지정가 진입 / 추가진입 / 분할 익절 / 익절·손절 — 화면에 뜨고 취소도 된다
 안 보인다 : 트레일링 스톱 / BTC 외 코인
 못 한다   : 밖에서 낸 진입 주문은 가격 이동 불가 (취소만 가능)

 ⚠ 밖에서 낸 추가진입 + 밖에서 청산 -> 그 주문이 안 치워진다
   (우리 기록에 없어서 정체를 모른다)
   -> 청산만이라도 우리 화면에서 하면 전부 정리된다

 ⚠ 밖에서 매매할 땐 바이낸스 "웹"에서 익절·손절까지 같이 걸어 주문할 것

-----------------------------------------------------
 G. 운영
-----------------------------------------------------
 · 재시작: 창 2개를 모두 닫고 start.bat. 하나라도 살아있으면 백엔드가 둘이 되어
   같은 계좌를 만지고 주문 기록 파일을 서로 덮어쓴다
 · 검은 창을 클릭해도 이제 안 멈춘다 (빠른 편집 모드를 껐다 — 2026-08-23)
 · 절전 모드는 컴퓨터가 멈추는 것이라 위험. 화면 꺼짐은 무해하다
 · 윈도우 자동 업데이트가 밤중에 재시작하면 아침까지 꺼져 있다.
   다시 켤 때 24시간이 지난 주문은 자동 복구 대상에서 빠진다
 · 이상하면 http://localhost:3002/api/health
   (account.changes가 안 늘면 감시가 죽은 것)
 · 근본 해결은 VPS에 백엔드만 올리는 것
